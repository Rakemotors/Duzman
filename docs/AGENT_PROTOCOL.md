# Agent Protocol (v1.7)

Описывает обязательные шаги исполнителя (Claude Code / Codex CLI)
при работе над задачей. Привязка к docs/TZ.md разделы 0.4, 0.5,
Приложение Г (8 полей), Приложение Ж (роли и forbidden actions).

## 1. Старт задачи

- Operator создаёт GitHub Issue, описание Issue содержит спеку
  в формате Приложения Г либо ссылку на спеку в репозитории
- Issue должен содержать заполненное поле "Зона спецификации"
- Без одобренного Issue исполнитель работу не начинает

## 2. Подготовка ветки

- git checkout main && git pull
- git checkout -b pr-<short-issue-name>

## 3. Реализация

- Все изменения только внутри объявленной "Зоны спецификации"
- Если требуется выйти за зону — остановиться и эскалировать
  по docs/TZ.md Приложение Ж.3
- Запрещённые действия — docs/TZ.md Приложение Ж.1

## 4. Definition of done (отчёт)

После завершения работы исполнитель прикладывает в тело PR:

1. Ссылка на связанный Issue (формат: "Closes #N" или "Refs #N")
2. Список изменённых файлов (вывод git diff --stat)
3. Явное подтверждение, что все изменения внутри объявленной
   Зоны спецификации
4. Вывод pytest -q (последние 20 строк) или явное указание
   "docs-only, тесты не запускались"
5. Чек-лист критериев готовности из спеки, каждый пункт
   PASS / FAIL + короткий комментарий
6. Хеш коммита (git log -1 --oneline)
7. Обновлён ли docs/ARCHITECTURE.md (да/нет, какая строка
   добавлена), либо явно "не требуется для docs-only"

## 5. Push и PR

- git push -u origin pr-<short-issue-name>
- Открыть PR в main с заполненным телом по пункту 4
- PR в main, не в protected branch напрямую

## 6. Ревью

- Reviewer-agent проверяет PR против Issue + docs/TZ.md +
  AGENTS.md/SKILL.md + diff + отчёт верификации
- Возможные вердикты: APPROVE, REQUEST_CHANGES,
  REJECT_SCOPE_VIOLATION, NEEDS_TZ_UPDATE
- Подробности — docs/TZ.md Приложение Ж.2

## 7. Merge и deploy

- Merge выполняет Operator после одобрения reviewer-agent
- Deploy — отдельная процедура, не часть PR workflow

## 8. Definition of failure

Задача считается проваленной если:
- Красные тесты
- Изменения в файлах вне Зоны спецификации без эскалации
- Отсутствие docstrings на новых публичных API
- Отсутствие обновления docs/ARCHITECTURE.md (когда требуется)
- Исполнитель замолчал в середине задачи

При провале задача передаётся другому исполнителю с пометкой
о состоянии или возвращается на доработку спеки по 0.4.
